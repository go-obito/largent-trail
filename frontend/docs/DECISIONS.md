# Frontend decisions

Reviewed 2026-10-20 against the official package documentation.

## Dependencies and runtime

- `idb-keyval` is added as the small IndexedDB key/value store for TanStack Query's signed-in-only persisted cache.
- `@types/node` is aligned to Node 24, the current LTS release. The local Node 26 runtime is Current, not LTS.
- The §2 stack is present: Next.js, React, TypeScript, MUI and its Next adapter, Emotion, Clerk, TanStack Query and persist client, OpenAPI tooling, React Hook Form and Zod, Zustand, Lucide, Tailwind, and Serwist. `@tailwindcss/turbopack` supplies Tailwind's selected Turbopack loader; Emotion packages support MUI. No other §2 dependency is missing.

## CSS and component styling

- Tailwind 4 uses its documented `@tailwindcss/turbopack` loader through `next.config.ts`; `globals.css` imports Tailwind and declares the MUI/Tailwind layer order. This avoids adding the separate PostCSS integration.
- MUI 9.5 documents the `v16-appRouter` cache provider, `enableCssLayer`, and the `@layer theme, base, mui, components, utilities` order for Tailwind 4. The declared layers let utilities override MUI styles.
- MUI's CSS-variable configuration supports a custom color-scheme selector. Both MUI and generated palette tokens use `<html data-theme="light|dark">`; default mode is system.

## Next.js compatibility

- Next.js 16 uses Turbopack by default and documents `next dev --webpack` / `next build --webpack` as the alternative.
- Serwist's `@serwist/next` getting-started guide is explicitly for webpack. Its Turbopack guide instead uses `@serwist/turbopack`, a Serwist route handler, and a different worker import. This is a real integration choice, not a configuration tweak: the frontend keeps the installed package and uses webpack for production builds rather than migrating to the different Turbopack integration.
- PWA wiring uses the documented `@serwist/next` webpack integration and disables Serwist outside production. The placeholder PNG icons are generated by `scripts/generate-pwa-icons.mjs`; replace them with final Largent artwork before launch.
- Next.js 16 renamed Middleware to Proxy. Clerk's current Next.js guide specifies `proxy.ts` (or `src/proxy.ts` when using `src/`); the frontend uses `src/proxy.ts` to protect application routes while leaving sign-in, sign-up, and offline pages public. Clerk's prebuilt sign-in and sign-up components inherit the generated palette tokens through Clerk's appearance variables.

## F1 dashboard

- Keep cached dashboard data visible when an offline refetch fails, provide a reduced-motion-aware manual refresh action, and use a placeholder `/transactions/new` route until F2.
- The profile's development-only token helper requests a fresh Clerk session token only on demand, copies it directly to the clipboard, and does not render in production.

## F3 budgets checkpoint 2

- Keep budget category and period immutable in edit mode; the edit form only submits a changed limit and archive state. Deletion remains a separate confirmed action.
- Create forms retain a client-generated UUIDv7 across retries, and prevent category/period duplicates against both active and archived budget records.
- Budget progress percentage and remaining/over amounts are display-only calculations from API amounts; status and status-driven colors remain based on the backend status.

## Visual system checkpoint 2

- The regenerated PWA assets use the recreated rounded Largent mark rather than a placeholder letter.
- All requested Lucide category icons are available in the installed `lucide-react` version; no substitutions were needed.

## F4 reports

- Give the report's net amount the dashboard hero treatment in a two-column totals layout; income and total spent stack beside it as supporting figures, matching the report hierarchy sketch.

## F5 needs checkpoint 1

- The generated frontend OpenAPI contract exposes CSV preview at `POST /v1/imports/preview`, but not the requested needs link preview at `POST /v1/needs/import-preview`. Do not call the unrelated CSV endpoint or hand-write an untyped route; add `useImportPreview` when the needs preview route is added to `apps/api/openapi.json` and regenerate the frontend schema.

## F7 onboarding checkpoint 2

- Save changed display name and timezone through `PATCH /v1/me`; use the device IANA timezone only as an explicit shortcut, and keep account creation online-first.
- Create first accounts with a stable client UUIDv7 across retries and show existing accounts and API balances before allowing the user to continue.
- Keep onboarding completion in the per-user browser flag until the API has an onboarded field. Recommend adding `users.onboarded_at` before relying on this state across devices.

## F7 onboarding checkpoints 3-4

- Starter budgets use the active expense categories returned by `useCategories("expense")`, suggest Food, Transport, and Airtime/Data when present, and create weekly budgets with client UUIDv7 IDs. A `409 duplicate_budget` is treated as an already-created budget.
- The introduction artwork is `public/manage-money-animate.svg`, a 500 by 500 SVG with a 271,516-byte source and embedded CSS animation. It has no opaque page-sized background; white and pale-gray fills belong to the illustration. The video container, step cards, and progress indicator use palette tokens so their surfaces follow both themes.
- The onboarding gate waits for `/v1/me`, active accounts, and the per-user local completion flag. The `/onboarding` route is exempt from the gate; a user with an active account is marked done, while a user without accounts is sent to onboarding unless the flag is `done` or `skipped`.
- The completion flag is stored as JSON (`status` and `timestamp`) in `localStorage` under `largent-onboarding:<Clerk user id>`. The current step is session-only in `sessionStorage` under `largent-onboarding-step:<Clerk user id>`. Replay uses `/onboarding?replay=1`, displays existing setup without writes, bypasses the gate, and leaves the completion flag unchanged.
- Recommend a backend `users.onboarded_at` field so onboarding status can eventually follow the user across devices instead of depending on browser-local storage.

## F7 public welcome page checkpoint 1

- `/welcome` is a public, indexable entry point. The F9 `robots.txt` must allow `/welcome`.
- The welcome intro uses the existing MP4 asset only on `/welcome`; the service worker excludes it from precache and uses network-only handling for video files.
- Open Graph and Twitter images use `NEXT_PUBLIC_SITE_URL` as their metadata base; set it to the canonical frontend origin for deployments.

## F7b accounts and categories checkpoint 1

- Account summaries aggregate only the backend-provided `balance_minor` values; the frontend never derives an individual account balance.
- The generated OpenAPI contract does not expose `reassign_to` on `DELETE /v1/categories/{category_id}`. Category deletion therefore uses only the declared path parameter. The `reassignTo` input and replacement choice are gated by `SUPPORTS_CATEGORY_REASSIGN` until the API schema exposes that field; when a category is in use, the UI offers archiving to preserve history.
- All 35 curated category icon keys are available in the installed Lucide version; no icon substitutions were needed.
