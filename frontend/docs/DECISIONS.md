# Frontend decisions

Reviewed 2026-10-20 against the official package documentation.

## Dependencies and runtime

- `idb-keyval` is added as the small IndexedDB key/value store for TanStack Query's signed-in-only persisted cache.
- `@types/node` is aligned to Node 24, the current LTS release. The local Node 26 runtime is Current, not LTS.
- The §2 stack is present: Next.js, React, TypeScript, MUI and its Next adapter, Emotion, Clerk, TanStack Query and persist client, OpenAPI tooling, React Hook Form and Zod, Zustand, Lucide, Tailwind, and Serwist. `@tailwindcss/turbopack` supplies Tailwind's selected Turbopack loader; Emotion packages support MUI. No other §2 dependency is missing.

## CSS and component styling

- Tailwind 4 uses its documented `@tailwindcss/turbopack` loader through `next.config.ts`; `globals.css` imports Tailwind and declares the MUI/Tailwind layer order. This avoids adding the separate PostCSS integration.
- MUI 9.5 documents the `v16-appRouter` cache provider, `enableCssLayer`, and the `@layer theme, base, mui, components, utilities` order for Tailwind 4. The declared layers let utilities override MUI styles.
- MUI's CSS-variable configuration supports a custom color-scheme selector. Both MUI and generated palette tokens use `<html data-theme="light|dark">`; default mode is system.

## Next.js compatibility

- Next.js 16 uses Turbopack by default and documents `next dev --webpack` / `next build --webpack` as the alternative.
- Serwist's `@serwist/next` getting-started guide is explicitly for webpack. Its Turbopack guide instead uses `@serwist/turbopack`, a Serwist route handler, and a different worker import. This is a real integration choice, not a configuration tweak: the frontend keeps the installed package and uses webpack for production builds rather than migrating to the different Turbopack integration.
- PWA wiring uses the documented `@serwist/next` webpack integration and disables Serwist outside production. The placeholder PNG icons are generated by `scripts/generate-pwa-icons.mjs`; replace them with final Largent artwork before launch.
- Next.js 16 renamed Middleware to Proxy. Clerk's current Next.js guide specifies `proxy.ts` (or `src/proxy.ts` when using `src/`); the frontend uses `src/proxy.ts` to protect application routes while leaving sign-in, sign-up, and offline pages public. Clerk's prebuilt sign-in and sign-up components inherit the generated palette tokens through Clerk's appearance variables.

## F1 dashboard

- Keep cached dashboard data visible when an offline refetch fails, provide a reduced-motion-aware manual refresh action, and use a placeholder `/transactions/new` route until F2.
- The profile's development-only token helper requests a fresh Clerk session token only on demand, copies it directly to the clipboard, and does not render in production.

## F3 budgets checkpoint 2

- Keep budget category and period immutable in edit mode; the edit form only submits a changed limit and archive state. Deletion remains a separate confirmed action.
- Create forms retain a client-generated UUIDv7 across retries, and prevent category/period duplicates against both active and archived budget records.
- Budget progress percentage and remaining/over amounts are display-only calculations from API amounts; status and status-driven colors remain based on the backend status.

## Visual system checkpoint 2

- The regenerated PWA assets use the recreated rounded Largent mark rather than a placeholder letter.
- All requested Lucide category icons are available in the installed `lucide-react` version; no substitutions were needed.
